# Five custom roles

Choose responsibility and authority first, then discover the relevant skills.
These are five available custom contracts, not a mandatory pipeline. The main session
owns dispatch, integration and canonical state; no role may proxy-dispatch.

| Role | Contract |
| --- | --- |
| researcher | Evidence, investigation and authorized analytical computation; no implementation or operations |
| planner | Decisions and planning artifacts; no execution |
| reviewer | Independent assessment and authorized focused verification; never repairs its candidate |
| auditor | Inspection only; no tests, edits, active scans or operational changes |
| operator | Explicitly authorized operational steps with target, preconditions, recovery and outcome checks |

Use actual native availability and supplied task contracts. Skills cannot expand
permissions. Code review uses review-code; staged delivery adds the full
review-story contract. Model and effort selection remain with the caller/runtime.
Definitions and fetched instructions do not prove live invocation.

## Native implementation

Implementation stays in the main session or uses an available native execution
agent: worker in Codex, general for OpenCode delegation, or build for ordinary
OpenCode primary development. Confirm actual runtime availability and authority;
these are native choices, not new custom definitions or aliases. Do not switch
the main session or dispatch a worker merely because a skill is loaded.

Supply owned paths, acceptance criteria, relevant skills, verification commands
and execution boundaries in the task packet. Discover prepare-handoff for packet
guidance when needed; run-agent-team supplies its own complete workflow contract.
Native worker selection does not prove that task-specific instructions were
received. The helper reads custom definitions and does not inventory built-ins.

Sources: [OpenAI subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)
and [OpenCode agents](https://opencode.ai/docs/agents/).

Resolve resources from the loaded skill, not sibling or cache guesses. Supply
relevant loaded guidance in delegated packets; parent loading does not prove
worker receipt. Discovery does not authorize installation or installed-file cleanup.
