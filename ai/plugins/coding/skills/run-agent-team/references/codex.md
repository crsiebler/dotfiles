# Codex team handoff

This is an invocation procedure, not a runtime adapter implementation. Resolve
trusted active-harness identity and inspect the tools actually exposed. Stop an
unsupported execution path rather than guessing argument names or role support.

## One preflight record

The main thread records in the existing execution checkpoint:
- Exact plan path/revision, approved outcome and branch/base scope.
- Exactly one dispatcher: native multi-agent-coordinator or disclosed main-thread
  guidance adoption. Record its actual ID/role/model evidence and limits.
- Main thread as sole integration/Git/canonical task-state owner, exact root/branch.
- Worker/model/delegation limits, occupied capacity, open/active semantics and
  required reviewer capacity, session continuation and supported release API.
- Exact callable coordinator/worker/reviewer selection, nesting support and pins.
- Existing execution, worktree, commit and closeout grants; missing scope/tools.

In delegated mode, select the existing native multi-agent-coordinator on Sol only
when exact role/model controls and nested worker/reviewer dispatch are supported.
Supply its bounded authority once; the parent does not dispatch another worker or
reviewer loop. In fallback mode, the Sol-selected main thread adopts discovered
coordinator guidance and dispatches direct workers. Disclose guidance adoption;
never claim it invokes the native role. No automatic model switch or installation.
Missing required reviewer controls blocks both paths; self-review is only the
existing risk-budget decision. No capability-probe agents. No proxy-spawning.

## Packets and nonrecursive entry

The coordinator packet includes approved plan path/revision, exact integration
root/branch/base, permitted assignments and lifecycle limits, worker-owned paths,
shared resources, model/role/capacity evidence and explicit sole dispatcher role.
The main thread prepares worktrees and returns verified base/ancestry evidence
before admission. The coordinator never creates another coordinator, changes Git,
merges, commits or writes canonical trackers. It dispatches workers and, on main
thread request, budgeted advisors/reviewers. Forward the complete unchanged review
protocol/profile/schema packet, not an inherited reference; retain the actual
native reviewer ID through its permitted targeted pass. No added review layer.

Every worker packet includes story ID/criteria, source requirements, delivered
prerequisite commits, absolute task worktree, exact branch/full base, bounded owned
paths/interfaces, private outputs, resource constraints, explicit model/specialist
selection and real check commands. Workers do not orchestrate, subdelegate, stage,
commit, merge or modify canonical task state. Return actual IDs, base/candidate,
changed paths, check evidence and blockers. Normal coding skill discovery applies.

The main thread integrates one candidate, runs required checks and supplies its
frozen review packet to the sole dispatcher. It owns remediation writes and final
marker/progress/memory/authorized commit operations. The coordinator may request
bounded worker remediation only after ownership is reconciled; never concurrent
writers to one candidate. Follow pre-commit evidence/provisional marker safeguards.

## Admission, acknowledgements and capacity

The dispatcher validates the plan DAG and fills Kahn-ready capacity in priority
then document order. Dispatch two independent eligible stories before waiting when
limits permit. Worker results do not release a dependency. Require the main thread's
delivery acknowledgement with successful integration checks/review, actual authorized
commit and current plan revision. Before dependent dispatch, require a clean base
containing acknowledged prerequisite commits and verified ancestry. Without an
acknowledgement, keep the dependent pending; stale snapshots never imply delivery.
Use the existing plan/checkpoint, not a new queue, task registry or execution loop.

Select Sol for the dispatcher, explicit Luna for suitable existing implementation
specialists and budgeted Astra for reviews/conflicts/architecture/cross-domain
analysis. Preserve exact dedicated reviewer roles, profiles, sessions and budgets.
Inspect actual installed pins and record unknown effective settings honestly.
Keep reusable role files unpinned; source text activates no installed settings.

Use min(requested worker limit, safely available native slots, model-use budget,
project resource capacity). Default to two workers. Count the main thread,
coordinator, all occupied sessions and actual nesting-depth limits. Reserve a
required reviewer slot or verify supported release of a completed worker; never
terminate a live writer or reviewer needed for its targeted pass. The integration
owner freezes only the reviewed candidate/conflicting resources; safely isolated
workers may continue. Reviews are not multiplied by ownership layers.

## Failure and restart

The main thread appends actual dispatch/integration owners, settings/IDs,
assignments/bases, checks/reviews, acknowledgements and consumed passes to
progress.md. The coordinator returns evidence rather than writing another journal.
Inspect actual native state and owned files after interruption. An uncertain
coordinator or worker may remain live; do not create a duplicate or proxy its work.
Missing identity or unresolved ownership blocks the affected path. Final blocked
review preserves candidate/history and consumed budget; new agents/models do not
resolve it. Continue only independently eligible safely isolated work.

Transfer only dispatch ownership, after the old dispatcher is quiescent and all
live assignments/reviewer sessions/budgets are reconciled. Main-thread Git and
canonical state ownership never transfers to a child. Unsupported nesting can use
the disclosed fallback only after these guards; it never waives reviewer controls.
Global stops stop the batch. After all verified delivery, quiesce writers and apply
required archival under actual authority. Preserve old plans if closeout fails.
