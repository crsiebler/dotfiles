# Requirements

Instruction-only inspection needs no package. Team execution requires
native spawn/follow-up/wait/session inspection and known capacity. Explicit model
selection is optional unless needed to satisfy a user requirement; use
[runtime selection](runtime-selection.md) for preferences, pins and fallbacks.
The current main session directly owns worker/reviewer dispatch, Git, worktree
lifecycle, integration and canonical state.
A custom coordinator role, custom primary selection, nested manager or reading
that role's instructions is not required.

Require an independent agent with the complete reviewer contract and
same-session continuation where the risk budget requires it. Follow
[reviewer binding](story-execution.md#reviewer-binding); a role selector is
optional unless explicitly required by the user or project. Inspect actual
schemas; invent no arguments,
model telemetry or tool capabilities. No proxy-spawning or bypassing the supplied
review contract. Ordinary native workers need no custom coordinator identity; any
required specialist identity must actually be supported. Inspect installed pins;
source omission is not installed inheritance.

Require Git, approved clean committed integration/task branches and worktrees,
this bundle's team delivery contract, the separately discovered review-story
contract and project-native verification tools.
Apply [autonomous execution scope](story-execution.md#autonomous-execution-scope):
checks must have an agent-executable, noninteractive path. Missing required
runtime capability blocks affected execution; tests or automation to be authored
in scope are valid implementation dependencies, not automatic launch blockers.
No manual test-result approval or routine deployment verification is required.
An explicit approved-plan implementation request includes initial and subsequent
scoped local commits; do not request that authority again. Lifecycle, model use
and sensitive actions retain their applicable scope requirements.
No automatic provisioning, installation, authentication or live capability probes.

Archival uses archive-run's helper and its declared Python/POSIX requirements;
resolve it from that loaded bundle. No environment creation.
Authoring validation uses create-skill's existing Python/PyYAML environment.
