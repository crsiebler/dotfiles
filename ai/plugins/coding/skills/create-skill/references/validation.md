# Validation and delivery

Run `check`, then `validate` for a project-owned skill copy. Packaging reopens the
ZIP, verifies its inventory/CRC/content against bounded source bytes, and publishes
only to a fresh output path. It excludes cache directories, .pyc/.DS_Store files,
and root evals; inspect any other project resources before including them.

Validate that the discovery description matches representative requests and excludes
nearby unrelated requests. Check reference/script closure from an installed copy,
then run meaningful operations from an unrelated working directory. Hash inputs
and installed resources before/after. No helper writes into its installed bundle.

Use valid and malformed frontmatter, mismatched name/directory, absent dependencies,
output collisions, escaping paths, symlinks, oversized inputs, and failed writes.
For evidence reports test absent metrics, true zero measurements, unequal sample
counts, summary disagreements, malformed grading, missing grading, and invalid
numbers. Unavailable telemetry is null, never a measured zero.

The schemas include illustrative model evaluation data, not recorded results.
Reports aggregate supplied evidence; they do not prove grading truth, model quality,
trigger precision, or visual quality. Inspect source artifacts separately and record
actual harness/model, commands, outcomes, skipped checks, and remaining limitations.
