# Accessibility

Use for user interfaces, interaction flows, validation, loading/error feedback
and content that affects access. Inspect semantic controls, names/labels,
relationships, keyboard operation, focus order/visibility/restoration, and dynamic
announcements. Consider disabled/loading/empty/error states and whether users can
understand, complete and recover from the task without a pointer or visual cues
alone. Check internationalized labels, directionality and content expansion where
the product supports them.

Source can reveal a missing label or unreachable handler but cannot establish
rendered contrast, focus behavior, screen-reader output or all viewport behavior.
Assess supplied rendered/browser/assistive-technology evidence with its actual
route, state, viewport, revision and tools. A screenshot alone does not prove
keyboard access or an accessible interaction; automated results cover only what
the actual check measures. Do not invent a compliance certification or measured
contrast value from markup.

Findings require a specific user action/state, affected access need, observed or
source-supported failure and practical remediation. Identify untested assistive
technologies or dynamic states as gaps, not successful verification. Propose later
authorized verification without opening a browser, running tools, editing code
or automatically invoking an accessibility specialist during review.
